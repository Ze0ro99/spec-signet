# SIGNET v1 normative pointer

SIGNET separates evidence, policy, allocation, receipt, and transparency planes. Engagement bodies are closed `SIGNET-PEP-v1` objects and are signed over `SIGNET-PEP-v1\n` plus canonical body bytes without `signature`. The verifier executes the frozen nine-step pipeline and consumes no pricing, chain state, or dashboard decisions.

Key certificates use `SIGNET-KEY-v1`; escrow, floor, allocation, and receipt artifacts use their dedicated domain prefixes in `src/core/canonical.js`. Policy packs only narrow an already-allowed crypto result. See the repository specification and tests for the normative compatibility surface.
